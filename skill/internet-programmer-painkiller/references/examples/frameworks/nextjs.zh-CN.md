# Next.js 示例

## 典型痛点
- 项目在一台机器上能运行，在另一台上却失败
- `npm install` / `pnpm install` 在不同环境中的表现不一致
- 热重载很慢或不稳定
- 环境变量缺失或没有文档说明
- 构建错误只会在 CI 中暴露出来

## 常见痛点类别
- 环境/配置漂移
- 反馈回路延迟
- 文档/可发现性缺口
- 工具链碎片化

## Hermes 示例提示词
```text
Use internet-programmer-painkiller.
我的 Next.js 应用在一台笔记本上能运行，但在另一台上不行。依赖安装和本地启动会以略有不同的方式失败。请诊断痛点类别，给出立刻可执行的最短路径修复，建议一个预防性工件，并告诉我接下来要衡量什么。
```

## 可能的最短路径修复
- 固定 Node 和包管理器版本
- 添加一条已验证可用的统一初始化命令
- 添加一条最小化的本地冒烟路径：安装 + 启动开发服务或构建
- 在 `.env.example` 中明确列出必需的环境变量
- 增加一个故障排查部分以减少猜测

## 好的预防性工件
- 已验证的快速开始文档
- 初始化脚本
- `.nvmrc` / 版本固定配置
- `.env.example`
- 在 CI 中镜像本地冒烟命令

## 指标
- 首次成功启动所需时间
- 配置步骤数量
- 与安装相关的 CI 失败次数
- 重复出现的配置问题数量
