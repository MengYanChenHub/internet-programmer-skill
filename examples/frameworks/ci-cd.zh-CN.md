# CI/CD 示例

## 典型痛点
- CI 比本地检查慢得多
- 不稳定任务总是被反复重跑
- 开发者不知道应该先关注哪个失败
- 代码评审总是在重复指出同样的问题
- 安全或策略检查在流水线后期才失败

## 常见痛点类别
- 反馈回路延迟
- 评审/安全/合规拖累
- 维护/运维负担过重
- 工具链碎片化

## Hermes 示例提示词
```text
Use internet-programmer-painkiller.
我们的团队在 CI 上等待太久，总要反复重跑不稳定任务，而且评审经常重复指出本应自动化解决的问题。请对痛点进行排序，建议最小但高杠杆的修复，并告诉我应该添加哪些预防性工件。
```

## 可能的最短路径修复
- 将快速门禁任务与慢速全量任务拆分开
- 添加一条与最有价值 CI 子集对应的本地冒烟命令
- 改进失败摘要，让第一个重要错误足够明显
- 对不稳定检查进行隔离，并指定负责人和截止时间
- 将重复性的策略与安全检查前移

## 好的预防性工件
- CI 阻力检查清单
- 带风险提示的 PR 模板
- flaky 测试负责人列表
- 更小但强制执行的冒烟流水线
- 更清晰的失败流水线诊断运行手册

## 指标
- CI 平均运行时长
- 每周 flaky 失败次数
- 每个 PR 的重跑次数
- 花在可重复问题上的评审评论数量
