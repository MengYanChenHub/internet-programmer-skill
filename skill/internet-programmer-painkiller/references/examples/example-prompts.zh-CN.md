# Hermes 示例提示词

## 1. 调试混乱
```text
Use internet-programmer-painkiller.
我正在调试一个后端问题，但一直在靠猜。请求有时成功，有时失败，我无法判断状态究竟是从哪里开始分叉的。请识别痛点类别，给出立刻可执行的最短路径修复、系统性修复，以及接下来要衡量什么。
```

## 2. 配置漂移
```text
Use internet-programmer-painkiller.
我们的项目在两位资深工程师的笔记本上能运行，但新贡献者在配置阶段总是失败。请诊断最可能的阻力类别，并给出一份黄金路径改进计划。
```

## 3. CI 拖慢节奏
```text
Use internet-programmer-painkiller.
我们的团队在 CI 上等待太久，而且总要反复重跑不稳定的任务。请对痛点进行排序，建议最小但高杠杆的修复，并告诉我应该创建哪些预防性工件。
```

## 4. 工具蔓延
```text
Use internet-programmer-painkiller.
我们用了太多仪表盘、脚本、机器人和部署入口。我想做一次阻力审计，在不强行进行大规模平台重写的前提下减少上下文切换。
```

## 5. 文档老化
```text
Use internet-programmer-painkiller.
开发者总是在聊天中反复询问相同的配置和故障排查问题。请把这当作文档/可发现性问题来分析，并提出能减少重复提问的最小修复方案。
```
