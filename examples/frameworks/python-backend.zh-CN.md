# Python 后端示例

## 典型痛点
- 调试时很难观察后端行为
- 本地环境与 CI 或生产环境不一致
- 依赖版本逐渐漂移
- 日志很多，但依然没什么帮助
- 同类事故反复发生，因为修复没有沉淀成运行手册

## 常见痛点类别
- 不可见状态
- 环境/配置漂移
- 维护/运维负担过重
- 文档/可发现性缺口

## Hermes 示例提示词
```text
Use internet-programmer-painkiller.
我正在调试一个 Python 后端，但一直在靠猜。请求已经进入服务，但我无法清楚看到数据库写入之前状态究竟从哪里开始分叉。请诊断痛点类别，给出立刻修复、系统性修复，以及接下来要衡量什么。
```

## 可能的最短路径修复
- 在请求生命周期周围增加结构化日志
- 添加请求 ID 或关联 ID
- 对比预期 payload 和实际 payload
- 捕获一个可复现的失败案例
- 将调试范围收窄到一个冒烟测试或一条请求路径

## 好的预防性工件
- 调试运行手册
- 事故到运行手册的转换流程
- 请求追踪检查清单
- 针对失败路径的冒烟测试
- 日志字段规范

## 指标
- 复现所需时间
- 定位根因所需时间
- 重复事故发生频率
- 手动调试步骤数量
